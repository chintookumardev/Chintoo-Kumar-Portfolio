# Code of Conduct

## Chintoo Kumar — Portfolio

Thank you for participating in the **Chintoo Kumar Portfolio** project.

This Code of Conduct establishes expectations for respectful, constructive, and professional participation in this project and its community.

I am committed to providing an environment where contributors, developers, students, designers, visitors, and other participants can communicate and collaborate respectfully.

---

## 1. Our Commitment

As the maintainer of this project, I am committed to:

- Maintaining a respectful and welcoming project environment.
- Encouraging constructive technical discussions.
- Welcoming contributions from people with different levels of experience.
- Considering feedback and suggestions in good faith.
- Addressing inappropriate behavior when it is reported.
- Maintaining a professional standard across project discussions and contributions.

Participation in this project should be based on mutual respect, professionalism, and constructive collaboration.

---

# 2. Expected Behavior

Everyone participating in this project is expected to behave respectfully and professionally.

Examples of expected behavior include:

### Be Respectful

Treat other contributors and participants with respect.

Different technical approaches, opinions, experience levels, and perspectives are expected in an open-source project.

### Be Constructive

When providing feedback:

- Explain the issue clearly.
- Focus on the code, documentation, design, or proposal rather than the individual.
- Suggest possible improvements when appropriate.
- Avoid unnecessarily negative or dismissive comments.

### Communicate Professionally

Use clear and appropriate language in:

- GitHub Issues
- Pull Requests
- Discussions
- Code reviews
- Project-related communication

### Welcome Different Experience Levels

Contributors may have different levels of knowledge and experience.

Beginners should feel comfortable asking questions and learning from the project.

Experienced developers are encouraged to provide helpful explanations and constructive guidance.

### Respect Project Scope

Contributions should generally relate to the purpose and goals of the project.

If a proposed change significantly changes the project's direction, discuss the idea before implementing a large change.

---

# 3. Unacceptable Behavior

The following behavior is not acceptable within project-related interactions.

## Harassment

Harassment, intimidation, or targeted personal attacks are not permitted.

## Discrimination

Discriminatory comments or behavior based on personal characteristics are not acceptable.

## Personal Attacks

Disagreements about code or technical decisions should not become personal attacks.

Examples include:

- Insulting contributors.
- Attacking someone's character.
- Mocking someone's abilities.
- Using deliberately hostile language.

## Trolling

Deliberately disruptive behavior intended to derail discussions or interfere with the project is not acceptable.

## Threats

Threats of violence, intimidation, retaliation, or other forms of harm are prohibited.

## Doxxing and Privacy Violations

Do not publish or distribute another person's private or personal information without appropriate permission.

This includes information such as:

- Private addresses
- Phone numbers
- Private email addresses
- Passwords
- Authentication credentials
- Private documents
- Other confidential information

## Spam

Do not use project Issues, Pull Requests, or Discussions for:

- Unsolicited advertising
- Repeated promotional messages
- Irrelevant content
- Automated spam
- Malicious links

## Malicious Contributions

Do not intentionally submit code, files, links, or other content designed to:

- Damage systems.
- Steal information.
- Introduce malicious software.
- Compromise user security.
- Circumvent security controls.

---

# 4. Technical Discussions

Technical disagreements are normal and encouraged when they remain constructive.

When discussing technical decisions:

1. Explain your reasoning.
2. Provide relevant technical evidence when possible.
3. Consider alternative approaches.
4. Respect other participants.
5. Focus on solving the problem.

For example, instead of:

> "This implementation is terrible."

Prefer:

> "This implementation may cause unnecessary complexity here. An alternative approach could be..."

The goal is to improve the project rather than to win an argument.

---

# 5. Code Reviews

Code reviews should focus on improving the quality, maintainability, security, and reliability of the project.

Reviewers should:

- Explain concerns clearly.
- Identify potential bugs.
- Suggest improvements where useful.
- Avoid personal criticism.
- Respect the contributor's effort.
- Distinguish between required changes and optional suggestions.

Contributors should:

- Consider review feedback in good faith.
- Ask questions when feedback is unclear.
- Explain technical decisions when necessary.
- Avoid taking technical criticism personally.

---

# 6. Pull Request Guidelines

Pull Requests should contain meaningful and relevant changes.

Contributors should:

- Provide a clear title.
- Explain what was changed.
- Explain why the change was made.
- Test changes before submitting.
- Avoid including unrelated modifications.
- Keep sensitive information out of commits.
- Respond respectfully to review feedback.

Large changes should preferably be discussed before implementation when they could significantly affect the project.

---

# 7. Issue Guidelines

Before opening an Issue, please check whether a similar Issue already exists.

When creating an Issue:

- Use a clear title.
- Describe the problem accurately.
- Provide steps to reproduce bugs.
- Include relevant screenshots or error messages.
- Mention the browser/device when relevant.
- Avoid personal or hostile language.

Issues should be used for legitimate project-related discussions.

---

# 8. Security Reports

Security vulnerabilities should not be publicly disclosed through a GitHub Issue before they have been reviewed.

Please report security-related issues privately using the contact information provided in:

**[SECURITY.md](SECURITY.md)**

Do not publicly post:

- Passwords
- API keys
- Access tokens
- Private credentials
- Exploit details that could unnecessarily expose users
- Other sensitive information

---

# 9. Privacy and Personal Information

Participants should respect the privacy of others.

Do not share personal information belonging to another person without their permission.

If personal information is accidentally published, notify the project maintainer so appropriate action can be considered.

---

# 10. Intellectual Property

Contributors should only submit content that they have the right to contribute.

Do not submit:

- Copyrighted material without permission.
- Proprietary code without authorization.
- Private company materials.
- Stolen designs or assets.
- Third-party content presented as your own.

When using third-party libraries, assets, or resources, contributors should respect their applicable licenses and attribution requirements.

---

# 11. Content Standards

Project-related contributions should remain relevant to the project.

Examples of appropriate contributions include:

- Bug fixes
- Feature improvements
- Documentation improvements
- Accessibility improvements
- Responsive design improvements
- Performance improvements
- Code quality improvements
- Security improvements
- Developer tooling improvements

Content unrelated to the project may be removed when necessary to keep discussions focused.

---

# 12. Communication

Project communication should remain professional.

Participants should avoid:

- Excessive profanity directed at individuals.
- Aggressive or hostile communication.
- Repeated arguments after a decision has been made.
- Deliberately provoking other participants.
- Derailing technical discussions.

Healthy disagreement is acceptable.

Disrespectful behavior is not.

---

# 13. Responsibilities of Contributors

Contributors are responsible for ensuring that their participation follows this Code of Conduct.

Before submitting a contribution, contributors should consider:

- Is the contribution relevant to the project?
- Is the code or content appropriate to submit?
- Have I tested my changes?
- Have I avoided sensitive information?
- Have I respected applicable licenses?
- Have I communicated respectfully?

---

# 14. Responsibilities of the Maintainer

The project maintainer may:

- Review reported conduct issues.
- Remove inappropriate comments or contributions.
- Close discussions that become abusive or disruptive.
- Request changes to contributions.
- Restrict participation when necessary.
- Take reasonable steps to maintain a respectful project environment.

Actions will depend on the circumstances and severity of the situation.

# 16. Confidentiality

Reports will be handled respectfully and, where reasonably possible, confidentially.

Information from a report may need to be shared when necessary to investigate or address the reported behavior.

The maintainer will avoid unnecessarily disclosing the identity of people who submit reports.

---

# 17. False or Malicious Reports

Reports should be made honestly and in good faith.

Deliberately submitting false reports, fabricating evidence, or using the reporting process to harass another participant may itself be considered inappropriate behavior.

This does not prevent anyone from reporting a concern made in good faith that later turns out to be mistaken.

---

# 18. Enforcement

Depending on the circumstances, violations may result in actions such as:

1. A request to stop inappropriate behavior.
2. A warning.
3. Removal or editing of inappropriate content.
4. Closure of an Issue, Pull Request, or Discussion.
5. Temporary restriction from project participation.
6. Permanent restriction from project participation.

The response will depend on the nature, severity, and context of the behavior.

---

# 19. Scope

This Code of Conduct applies to project-related interactions, including but not limited to:

- GitHub repository activity
- Issues
- Pull Requests
- Discussions
- Code reviews
- Documentation contributions
- Project-related communication

It also applies when a participant is representing or directly interacting with the project in another project-related context.

By contributing to or participating in this project, you agree to:

- Communicate respectfully.
- Provide constructive feedback.
- Respect other participants.
